# Crate & Cards Arcade

A Chrome extension (Manifest V3) with three games behind one wallet:

| Game | What it is |
|---|---|
| **Sokoban** | 24 hand-authored warehouses. Every level ships with a machine-proven move-optimal solution, which sets its par, its star thresholds and what the Hint item reveals. |
| **Klondike Solitaire** | Draw-one or draw-three, click-to-move with double-click auto-place, unlimited undo, one-click finish once the board is open. |
| **Cipher Duel** | An original two-player card game. Higher rank takes the round — unless your suit *counters* theirs (♠→♥→♦→♣→♠), which halves their card. Reading what the opponent has already spent is the edge. |

Coins earned in any game spend in any other. Gems are the premium currency: earned
slowly through the daily streak and achievements, or bought in packs.

## Install it

```bash
cd packages/sokoban-extension
npm run verify        # static checks + the full test suite
```

Then in Chrome: **chrome://extensions** → enable *Developer mode* → **Load unpacked** →
select this directory. The arcade opens on install; afterwards use the toolbar icon.

`npm run package` writes `dist/crate-and-cards-<version>.zip` for the Web Store.

## Scripts

| Command | What it does |
|---|---|
| `npm test` | Runs the engine, card and economy suites. |
| `npm run check` | Manifest references resolve, every module parses, no remote scripts, no inline handlers. |
| `npm run levels` | Re-solves every level and regenerates `solutions.js`. **Run this after editing `levels.js`** — an unsolvable level fails the build. |
| `npm run icons` | Rasterises the icon set (pure node, no image libraries). |
| `npm run package` | Builds the upload zip. |

## The wallet, and why the page can't touch it

Only the service worker reads or writes the profile. A game page never adjusts a
balance; it sends a *claim* and the worker re-derives the truth:

* **Sokoban** — the page sends the move string it played. The worker replays it
  through the same engine and pays out only if the crates really end on the goals.
* **Solitaire** — the page sends the deal's seed and its move list. The worker
  re-deals from the seed and replays every move; an illegal move voids the claim.
* **Duel** — the worker issues the seed (and charges the ticket) *before* the duel
  starts, and only accepts a result for a seed it issued. The opponent's policy is
  deterministic, so the whole duel replays exactly.

Everything else follows from that: writes are serialised through one mutation
queue so two tabs can't interleave a read-modify-write, payouts per level are rate
limited, and every balance change is appended to a capped ledger you can read in
the Wallet tab.

Storage is `chrome.storage.local`. The only permission the extension requests is
`storage`; there is no host access, no content script, no analytics and no network
call at all unless you configure a payment provider.

## Economy

Balancing lives in one file — `src/store/catalog.js`:

* **Payouts** `REWARDS` — first clear 40 coins + up to 60 for stars, a gem for a
  move-optimal clear; solitaire 60 (85 with no undo) or 2/card for a part-finished
  deal; duel 45 + 4/round + a streak bonus that caps at 5×.
* **Sinks** `STORE_ITEMS` — consumables (undos, hints, skips, duel peeks,
  insurance, hand swaps), permanent upgrades (Coin Doubler, Deep Undo, Rapid
  Tickets) and cosmetics (three themes, two card backs).
* **Tickets** — Duel costs one of five tickets, regenerating every 20 minutes.
  Sokoban and Solitaire are never gated, so nothing behind a paywall blocks
  progress: gems buy convenience and cosmetics, never levels.

## Wiring up real payments

`src/config.js` ships with `provider: 'sandbox'`: purchases are simulated locally,
every surface says so, no money moves and no card details are requested. That
keeps the unpacked extension safe to load and to review.

Chrome removed the Web Store payments API, so real money has to go through your own
processor. Set `provider: 'checkout'` and fill in two URLs:

```js
checkoutUrl: 'https://pay.example.com/buy',   // opened as ?sku=…&uid=…
verifyUrl:   'https://pay.example.com/entitlements',  // polled as ?uid=…
```

* `checkoutUrl` is opened in a tab; your page takes payment however you like
  (Stripe Checkout, Paddle, whatever) using the `sku` and the install's `uid`.
* `verifyUrl` must return, **from your server**, only orders you have confirmed as
  paid:

  ```json
  { "entitlements": [{ "sku": "gems_550", "receiptId": "order_1KpX…" }] }
  ```

The extension grants a `receiptId` exactly once — it is recorded in the profile and
a repeat is rejected as `duplicate_receipt` — and one-time bundles are refused a
second time even with a fresh receipt. Nothing is granted on a client-side
"success" signal; the worker only believes your server. You will also need to add
your verification host to `host_permissions` in the manifest.

"Restore purchases" is the same entitlement call, which is what a reinstall needs.

## Publishing notes

Two things to know before submitting to the Chrome Web Store:

1. **Payments must be disclosed.** Listings that sell digital goods have to state
   it, and the checkout flow has to be honest about what is charged and when.
2. **This is deliberately not a casino.** Purchasable chips wagered on chance-based
   outcomes fall under the gambling policy (and real-money gambling law in many
   places). Both card games here are skill-based, and gems buy items and cosmetics
   rather than bets, which keeps the extension outside that category. If you fork
   this into a wagering game, that is a very different compliance problem.

## Adding a level

Append to `src/games/sokoban/levels.js` using the standard characters
(`#` wall, `.` goal, `$` box, `*` box on goal, `@` player, `+` player on goal),
then:

```bash
npm run levels && npm test
```

The solver is a move-optimal BFS with dead-square pruning. It refuses to write
`solutions.js` if any level is unsolvable, has mismatched box and goal counts, or
has no player — so a broken level can never ship.
